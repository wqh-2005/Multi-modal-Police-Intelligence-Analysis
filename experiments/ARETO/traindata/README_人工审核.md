# 100篇人工训练标注试点

本批全部是待人工审核的候选，不是金标。复用已完成的大模型单篇抽取结果，没有重新调用API，没有修改正在运行的抽取代码、输入或输出。

## 文件

- `raw/selected_cases_100.json`：100篇完整原始记录，保留原始编号、案件类别、案情描述。
- `llmdata/case/<source_id>.json`：每篇一个可编辑的候选标注文件，包含全文、实体、提及、关系、事实状态和证据。
- `schemas/`：本批实体、角色、关系定义的快照。
- `selection_manifest.json`：抽样种子、类别统计、来源文件和自动对齐统计。
- `prepare_review_batch.py`：可追溯的生成程序；已有文件时拒绝覆盖，避免覆盖人工修改。

从现有case_weak_v1训练划分内、已有成功且非空抽取结果的案例中抽样。刷单返利10篇，其余10类各9篇，兼顾短、中、长文本，排除完全重复文本。这是训练标注试点，不代表总体自然分布，也不是独立测试集；已成功、非空结果的筛选存在偏差。

## 审核顺序

1. 通读`text`，不能只核对已有候选；补充遗漏关系。
2. 核对`entities`：实体名称、类型、角色是否有依据；删除猜测，按需合并或拆分实体。
3. 核对`mentions`：列出该实体实际出现的原文提及，包括有充分依据的代词和别名。程序仅自动填入规范名称的所有字面出现位置，没有自动解决共指。不能把这些出现位置全部当作已确认的同一实体。
4. 核对`relations`：头尾实体、关系、方向、事实状态及证据。要求执行不代表实际发生。
5. 填写`mention_pairs`：指定实际支持关系的实体提及。候选ID仅是定位辅助，不是标准答案。即使程序填入唯一候选，也仍要人工确认。
6. 确认没有遗漏后，填写`review.reviewer`、`review.reviewed_at`及`review.checked_for_missing_relations=true`，将`annotation_status`改为`人工审核完成`。子项`review_status`可改为`人工确认`。这表示个人审核完成，不自动表示已经过双人独立标注和裁定。

不要改`text`中的空格、标点或换行，否则已有字符位置会失效。原始数据里的错别字也先保留，必要时写在审核备注中。

## 字符位置

位置基于Python字符串字符索引，0开始，左闭右开。必须满足`text[start:end] == mention.text`。不是UTF-8字节位置，也不是token位置。

例如`张三联系李四。他要求李四下载某APP。`：

```json
{"mention_id":"M3","start":7,"end":8,"text":"他"}
```

`mention_id`全篇唯一。新增提及时用未占用的编号；关系引用必须指向对应头、尾实体的提及。

```json
"mention_pairs": [
  {"head_mention_id":"M3","tail_mention_id":"M5"}
]
```

关系允许多组确实成立的提及对，不要把所有位置做笛卡尔积。`candidate_head_mention_ids`、`candidate_tail_mention_ids`是自动辅助字段，人工修改后可删除；训练将以已确认的`mention_pairs`为依据。

## 非字面名称、隐含实体和共指

`mentions: []`并不表示实体一定隐含，只表示程序没有找到规范名称的字面片段。先查找原文中的真实名称、代词、简称或角色称呼；有可靠依据时补充提及并归入同一实体。

如果主体确实完全省略，不要虚构位置。保留空提及，添加`implicit: true`和`review_note`说明依据；这类关系保留在完整标注中，后续单独报告原版ARETO无法直接进行跨度监督的情况。若完全没有依据，应删除该候选，而不是补写事实。

## 证据与无关系文档

`evidence`已经按抽取时的原文单元恢复位置，但语义是否支持关系仍需人工判断。可收窄证据范围，修改后保持`text[start:end]`与证据文本相等。跨句关系可有多段证据。

如果整篇没有任何符合schema的关系，设置`relations: []`并在备注说明，保留文档，不要删除文件。

## 训练前

当前格式是人工审核主格式，当前ARETO加载器尚不能直接读取，需要后续转换为明确的字符/token跨度标签。金标与伪标签分开记录；本批ID应保持为训练/开发用途，不能随后混入独立论文测试集。审核后建议把确认版本另存到`golddata/case`，保留本批候选供追溯。
