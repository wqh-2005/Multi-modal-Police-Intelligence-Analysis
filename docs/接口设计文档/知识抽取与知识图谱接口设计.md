### 3. 内部协作契约 (实现后端并行的关键)

为了让 **开发人员 C** 不需要等 B 写完知识抽取和存储就能开工，我们必须在代码层面固定 **“交接棒”** 的样子。

#### 3.1 共享模型定义 (app/models/knowledge_schema.py)

**这是 B、C 都要引用的文件。**

```
from pydantic import BaseModel
from typing import Optional, List

# ---------- 格式 1.3：知识抽取输出 ----------

class Triplet(BaseModel):
    """三元组"""
    subject: str              # 头实体
    subject_type: str         # 头实体类型 (PERSON/PHONE/ACCOUNT/ORGANIZATION/...)
    predicate: str            # 关系 (冒充/转账给/威胁/...)
    object: str               # 尾实体
    object_type: str          # 尾实体类型
    confidence: float         # 该三元组置信度 (0-1)
    evidence: str             # 原文证据片段

class Entity(BaseModel):
    """实体"""
    name: str                 # 实体名称
    type: str                 # 实体类型
    subtype: Optional[str]    # 子类型 (victim/suspect/normal)
    properties: dict          # 属性键值对

class ExtractionOutput(BaseModel):
    """
    这是模块二产生的'交接棒'对象
    开发人员 B：必须生成这个对象
    开发人员 B（存储模块）：以此对象作为函数的输入
    """
    triplets: List[Triplet]           # 三元组列表
    entities: List[Entity]             # 实体列表
    raw_text: str                      # 原始文本
    extraction_confidence: float       # 整体置信度 (0-1)
    case_id: str                       # 案件ID (贯穿全流程)

# ---------- 格式 1.4：知识存储输出 ----------

class Victim(BaseModel):
    """受害者信息"""
    name: str = "未知"
    age: int = 0
    profession: str = "未知"
    phone: Optional[str] = None
    id_card: Optional[str] = None

class Suspect(BaseModel):
    """嫌疑人信息"""
    name: str = "未知"
    phone: Optional[str] = None
    account: Optional[str] = None

class Relation(BaseModel):
    """实体关系"""
    from_entity: str          # 来源实体
    type: str                 # 关系类型
    to_entity: str            # 目标实体

class Transaction(BaseModel):
    """资金交易"""
    from_entity: str
    to_entity: str
    amount: float
    time: Optional[str] = None   # ISO 8601

class GraphStorageOutput(BaseModel):
    """
    这是模块三产生的'交接棒'对象
    开发人员 B（存储模块）：必须生成这个对象
    开发人员 C：以此对象作为函数的输入
    """
    victim: Victim                    # 受害者信息
    suspect: Suspect                  # 嫌疑人信息
    relations: List[Relation]         # 实体关系列表
    transactions: List[Transaction]   # 资金交易记录
    chat_history: str                 # 原始聊天记录（截断至500字）
    case_id: str                      # 案件ID (贯穿全流程)
```

### 4. 知识抽取规则（实体与关系定义）

#### 4.1 实体类型

| 类型 | 标识 | 说明 | 优先级 |
|------|------|------|--------|
| PERSON | 人员 | 受害人 / 嫌疑人 | 高 |
| PHONE | 电话 | 手机号 / 座机号 | 高 |
| ACCOUNT | 账户 | 银行卡号 / 支付账号 | 高 |
| ORGANIZATION | 机构 | 公安局 / 银行 / 公司 | 高 |
| AMOUNT | 金额 | 涉案金额 | 高 |
| TIME | 时间 | 案发/转账时间 | 中 |
| ID_CARD | 身份证 | 公民身份证号 | 中 |
| URL | 链接 | 钓鱼网站 / APP链接 | 中 |
| PLATFORM | 平台 | QQ / 微信 / 抖音 | 低 |
| LOCATION | 地点 | 见面地点 / IP归属地 | 低 |

#### 4.2 关系类型

| 关系 | 主语→宾语 | 示例 |
|------|-----------|------|
| 冒充 | PERSON→ORGANIZATION | 骗子 冒充 公安局 |
| 转账给 | PERSON→PERSON/ACCOUNT | 受害者 转账给 骗子 |
| 威胁 | PERSON→PERSON | 嫌疑人 威胁 受害者 |
| 声称涉嫌 | ORGANIZATION→PERSON | 公安局 声称涉嫌 受害者 |
| 提供账户 | PERSON→ACCOUNT | 嫌疑人 提供账户 6222*** |
| 发送链接 | PERSON→URL | 嫌疑人 发送链接 钓鱼网站 |
| 要求下载 | PERSON→PLATFORM | 嫌疑人 要求下载 虚假APP |
| 添加好友 | PERSON→PERSON | 嫌疑人 添加好友 受害者 |
| 拨打电话 | PERSON→PHONE | 嫌疑人 拨打电话 138**** |
| 诱导投资 | PERSON→PLATFORM | 嫌疑人 诱导投资 虚假平台 |
